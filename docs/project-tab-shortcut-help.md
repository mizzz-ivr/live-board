# キーボードショートカット一覧

## 目的

Projectタブで利用できるキーボード操作をアプリ内から確認できるようにし、ショートカットの発見性とアクセシビリティを改善します。

## 起動方法

次のどちらからでも一覧を開けます。

- Projectタブ操作領域の`?`ボタン
- 入力欄以外で`?`キーを押す

`?`キーは既存のProjectタブショートカットと同じ判定経路を利用します。入力欄、IME変換中、キーリピート中、処理済みイベントでは開きません。

## 表示内容

一覧は`PROJECT_TAB_SHORTCUT_GROUPS`から生成します。表示文言をコンポーネントへ直接重複定義せず、キー判定とヘルプ表示が同じ定義を参照します。

### Projectタブ操作

- `F2`: アクティブProject名を変更
- `Ctrl/Cmd + W`: アクティブタブを閉じる
- `Ctrl/Cmd + Shift + T`: 閉じたタブを復元
- `?`: ショートカット一覧を表示

### タブ移動・並び替え

- `← / →`: 前後のタブへ移動
- `Home / End`: 先頭・末尾のタブへ移動
- `Ctrl/Cmd + Shift + ← / →`: 同じピン留め領域内で並び替え

## モーダル設計

ネイティブ`dialog`と`showModal()`を使用します。

- モーダル表示中は背面UIをinertにする
- 開いた直後は閉じるボタンへフォーカスする
- Tab移動をモーダル内に制限する
- Esc、閉じるボタン、背景クリックで閉じる
- 閉じた後は起点要素へフォーカスを戻す
- 見出しと説明を`aria-labelledby`、`aria-describedby`で関連付ける

独自フォーカストラップを実装せず、Electronが利用するChromiumのネイティブ挙動へ寄せます。

## ショートカット競合の扱い

モーダル表示中にProjectタブ操作のショートカットを認識した場合は、イベントの既定動作と伝播を抑止しますが、Project操作は実行しません。

特に`Ctrl/Cmd + W`を抑止することで、一覧表示中にProjectタブまたはElectronウィンドウが意図せず閉じることを防ぎます。`?`を再度押した場合は一覧を閉じます。

## 影響範囲

変更対象:

- ProjectタブUI
- Projectタブショートカット定義
- ショートカット一覧ダイアログ
- Desktop Unit Test
- Playwright E2E

変更しない範囲:

- Workspace Command履歴
- `.liveboard`保存形式
- Projectタブ永続化形式
- Electron IPC
- OBS Protocol
- Broadcast Snapshot

## テスト観点

### Unit Test

- `?`を一覧表示Actionへ解決する
- 入力中とキーリピート中は`?`を無視する
- 一覧項目IDが重複しない
- 主要操作とナビゲーション項目がすべて含まれる

### Playwright E2E

- ボタンと`?`キーから一覧を開ける
- 開いた直後に閉じるボタンへフォーカスする
- Tab移動がモーダル内に留まる
- Escで閉じ、起点ボタンへフォーカスを戻す
- 背景クリックで閉じる
- モーダル表示中の`Ctrl + W`でProjectタブを閉じない
- 入力欄内の`?`で一覧を開かない
